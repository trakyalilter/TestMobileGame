## CONFIRMED — real defects (adversarially verified)

### 1. [MAJOR] hard_reset misses 6 NG+ flags — Sectors 13–15 stay unlocked on a New Game
`game_state.gd:580` erases only `z10_cleared`/`z11_cleared`/`z12_unlocked`(/`z11_unlocked`),
but gameplay also sets `z12_cleared`/`z13_cleared`/`z14_cleared` (combat_manager.gd:3846-3853)
and `z13_unlocked`/`z14_unlocked`/`z15_unlocked` (warp_manager.gd:252-259). `game_settings`
survives hard reset wholesale and is saved wholesale, so on a fresh New Game **Sectors 13–15
are visible and enterable from minute one** while Z11/Z12 are correctly re-locked — inverted
gate order. Intent is explicit at warp_manager.gd:251 ("cleared only on hard reset"): this is
a v137 omission, not design. **Fix:** erase all six flags in `hard_reset()`.

### 2. [MAJOR] Skill.reset() keeps unlocked_milestones — ghost milestone buffs after warp
`skill.gd:125` decays xp and re-derives level but never clears `unlocked_milestones`;
`_check_milestones` is append-only. After a warp (30% keep drops ~12 levels) the old
milestones stay "unlocked" for the rest of the session: processing speed ×1.10/@10 ×1.11/@25,
milestone-50 double-output roll, infrastructure milestone-10 bonus all keep paying. Also
swallows the re-cross toast (milestone already in the array → `milestone_unlocked` never
re-fires). Self-heals on app restart only (array is derived at load, not saved). **Fix:**
clear the array in `reset()` and re-derive from the post-decay level.

### 3. [minor] Cryo hits float as "KIN"; cryo WEAK SPOT never fires
`combat_manager.gd:2969` classifies damage labels only as K/E/X — a pure-cryo weapon
(Cryo Lance / Corrosion Blaster, k=e=x=0) falls to the default and every Z11+ hit floats
as "-N KIN"; the RESISTED/WEAK SPOT line reads only resist_k/e/x so `resist_cryo -0.25`
never shows WEAK SPOT. The one place the game should confirm the Cryo lesson mislabels the
damage as the type the gate just nullified. Damage itself resolves correctly; feedback-only.
**Fix:** add a CRY branch (p_atk_cryo dominant → "CRY", dominant_resist = resist_cryo);
combat_page already styles CRY (combat_page.gd:1504-1506).

### 4. [minor] main_menu_ui_check probe is stale — scene errors and hangs to timeout
Commit 4729659 (v161) replaced the offline-combat CheckBox `chk_offline_combat` with the
segmented pill `pill_offline_combat`; the committed probe (`scripts/sim/main_menu_ui_check.gd:33`)
still reads the old property → guaranteed SCRIPT ERROR before its only `quit(0)`, hangs at
110s and 300s. The player-facing toggle itself is fine (sync path uses
`UITheme.set_pill_value`, which never fires the callback — the spurious-dialog bug it guards
stays structurally fixed). **Fix:** one-line probe update to the pill property.

## UNVERIFIED MAJORS (verifier lost / overflow — treat as probable until checked)

### A. zone_gate_check: all 9 zone transitions "LEAK" (verifier died on session limit)
The probe reports maxed Z(n) gear still kills Z(n+1) e3 trash for every transition Z1→Z10
(e.g. maxed-Z9 kills z10 trash in 14k ticks vs 8k for common Z10 gear — ~75% slower, but it
lands). **This needs a design ruling more than a code fix:** in a Melvor-shaped game,
slowly farming next-zone trash with old gear to bootstrap the new tier is arguably the
intended loop; a hard gear wall would be the anomaly. The probe's "wall" expectation may be
aspirational. Decide the intent, then either retune or rewrite the probe's pass criterion.

### B. HOW TO PLAY still says "Quests" (main_menu.gd:549)
The 8-section main-menu briefing points new players at a "Quests" tab that no longer exists
(sidebar says "Orders"), and none of its strings are in strings.csv — the whole briefing
ships raw English under the Turkish locale.

### C. Orders first-visit coach body untranslated (coach_marks.gd:212)
The body was rewritten during the rename but never added to strings.csv; the OLD body
survives as an orphaned row (strings.csv:2206). Turkish players see this one card in
English while its sibling rows are translated.
